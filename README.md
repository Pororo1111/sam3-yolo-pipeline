# sam3-yolo-pipeline

YouTube URL, 웹캠, 비디오 파일, 이미지 폴더를 입력으로 받아 프레임 추출부터 SAM3 오토라벨링, YOLO 학습, 추론, 침입 감지까지 실행하는 Gradio WebUI입니다.

## 주요 기능

- 프레임 추출: YouTube URL, 웹캠, 비디오 파일, 이미지 폴더 지원
- SAM3 오토라벨링: 텍스트 프롬프트 기반 마스크 생성 및 YOLO bbox 변환
- 데이터셋 검토/구성: 라벨 확인, 클래스명 편집, train/val 분할
- YOLO 학습: 학습 로그 스트리밍, 결과 모델 저장
- 추론: 학습된 모델로 영상/이미지 소스 추론
- 침입 감지: 모델의 실제 학습 클래스(예: `traffic_cone`)를 선택해 자동 추적 영역을 만들고 영역 내 객체 감지
- 샘플 불러오기: `samples/`의 URL, 비디오, 이미지 폴더를 카드 버튼으로 선택

## 추론·침입 감지

두 탭의 **탐지 주기 (초)** 기본값은 **1초**입니다. 첫 프레임은 즉시 탐지하고, 이후 실제 경과 시간에 따라 YOLO 추론·ByteTrack 추적을 실행합니다. 탐지 사이에는 마지막 결과를 표시하며, 이미지 폴더도 기본 1초 주기로 처리합니다. 모델 처리 자체가 1초보다 느리면 실제 탐지 간격은 더 길어집니다.

접속 기기 웹캠은 원본 영상 위에 감지 박스와 감시 영역을 겹쳐 표시합니다. **추론 시작 / 스트림 시작**으로 카메라 전송을 함께 시작하며 별도 녹음 버튼은 표시하지 않습니다. 침입 감지는 모델 선택 후 **자동 영역 추적 클래스**를 선택하세요. 선택한 클래스의 Track이 3개 이상 검출되면 해당 클래스명으로 자동 영역을 생성합니다.

## 데이터 누적 사용법

1. 프레임 추출을 다시 실행하면 기존 이미지·라벨을 보존하고 새 소스를 추가합니다. 수집 ID는 `yt001`, `yt002`, `video001`처럼 충돌 없이 발급됩니다.
2. 수집 완료 후 라벨링 탭에는 새 소스가 선택됩니다. 기본 **미처리만**은 라벨 파일이 없는 이미지만 처리합니다. 기존 결과를 바꾸려면 **선택 소스 재라벨링**을 선택하세요. 빈 라벨 파일은 객체 없는 처리 완료 결과입니다.
3. 클래스 ID와 이름은 `dataset/classes.json`에 보존됩니다. 프롬프트 순서가 바뀌어도 기존 ID를 사용하며 새 클래스만 뒤에 추가합니다. 클래스 이름을 편집해도 이전 프롬프트와의 연결은 유지됩니다.
4. 기존 데이터에 YAML 클래스 정보가 없으면 `class_0` 등의 미확인 이름으로 표시됩니다. 데이터셋 검토 단계에서 실제 이름을 지정한 뒤 새 라벨링을 실행하세요. 최신 프롬프트를 과거 라벨의 이름으로 자동 적용하지 않습니다.
5. 데이터셋 구성은 누적 원본으로부터 train/val을 다시 만듭니다. validation 선택을 비우면 기존 배정을 유지하고 새 소스만 추가 배정합니다. 직접 선택하면 선택한 소스와 동일 원본의 수집분을 validation으로 배정합니다. 미처리 이미지는 학습에서 제외합니다.

`sources.json`에는 소스·수집 시각·장수·완료/중단 상태, `split_manifest.json`에는 분할 배정을 저장합니다. 이전 파일명은 그대로 사용합니다. 같은 YouTube 영상은 URL 형태와 관계없이 묶고, 새로 수집하는 비디오 파일은 내용 해시로 동일 원본을 구분합니다. 원본을 알 수 없는 예전 수집분은 기존 소스 그룹을 유지합니다.

라벨은 이미지별 추론 성공 후 교체합니다. 학습용 폴더는 임시 위치에서 준비·검증한 뒤 교체하며, 복사 실패나 준비 중 취소 시 직전 결과를 보존하고 교체 중 예외 발생 시 복원합니다. 프로세스 강제 종료나 전원 장애까지 보장하는 다중 파일 트랜잭션은 아닙니다.

## 설치

CUDA 환경:

```powershell
bash install_cuda.sh
```

CPU 환경:

```powershell
bash install_cpu.sh
```

스크립트는 `venv`를 만들거나 재사용한 뒤 PyTorch 빌드(CUDA/CPU)를 먼저 설치하고, 나머지 의존성을 설치합니다.

## 모델 준비

`models/` 폴더에 아래 파일을 배치합니다.

- `sam3.pt` — Hugging Face에서 모델 접근 승인을 받은 뒤 다운로드: https://huggingface.co/facebook/sam3
- `yolo26m.pt` — 없으면 Ultralytics가 필요 시 자동 다운로드

## 실행

```powershell
venv\Scripts\Activate.ps1
gradio app.py
```

브라우저에서 `http://localhost:7860`에 접속합니다.

웹캠 목록은 **앱 서버에 연결된 카메라**를 먼저 표시하고, `서버 + 접속 기기
카메라 검색`을 누르면 카메라 권한을 요청한 뒤 현재 브라우저(모바일 포함)의
카메라를 이어서 표시합니다. 접속 기기 카메라를 선택한 경우 표시되는 카메라
입력에서 스트리밍을 먼저 시작한 뒤 프레임 추출·추론·침입 감지를 시작하세요.

브라우저 카메라 API는 보안 컨텍스트에서만 동작하므로 원격 모바일 접속에는
**HTTPS가 필요**합니다(`localhost` 접속만 HTTP 예외). Raspberry Pi의 서버
카메라는 USB/V4L2 장치(`/dev/video*`) 권한과 다른 프로세스의 카메라 점유
여부를 먼저 확인하세요.
